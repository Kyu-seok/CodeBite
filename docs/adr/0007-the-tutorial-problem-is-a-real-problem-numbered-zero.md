# The Tutorial Problem is a real problem, numbered zero

The Tutorial runs on a real, published problem rather than a practice problem kept outside the catalogue. Its first Accepted counts like any other: the problem becomes Solved, the day becomes a Streak Day, and a linked GitHub account gets a Solution Commit. The Tutorial is for people new to coding practice, and its goal is their first Accepted in their first session. That Accepted should leave them with something real (a Streak of 1, a Solved count of 1) rather than a result that vanishes once the guide is over. The Tutorial Problem is numbered 0, labelled as the Tutorial in the list, and kept out of every curation, the Roadmap and recommendations, so experienced users never have it counted against a curation or suggested to them.

## Considered Options

- **A practice problem that counts for nothing.** It would keep the catalogue, Acceptance Rates and stats untouched. But the newcomer's first success would leave no trace, and it would be a second kind of problem that the workspace, the submission flow and the stats would all have to tell apart.
- **Number 1, inside CB50 and CB100.** It would be simpler, but every curation's progress would include a trivial problem and the Roadmap would open with it.
- **The next free number.** It would be invisible to curations by accident rather than by rule, and the Tutorial Problem would sit at the end of the list, where nobody finds it.

## Consequences

Curations select problems by number up to a limit, so number 0 falls inside every one of them unless the query also requires a number of at least 1. Every curation query, the Roadmap and recommendations must exclude it explicitly. The Tutorial Problem's Acceptance Rate will sit near 100% and is not a signal about the catalogue. Undoing this later means deciding what happens to users who have it Solved, to the Streak Days it gave them and to its Solution Commits, which is why the choice is recorded here.
